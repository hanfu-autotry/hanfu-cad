# 02 许愿手册（指令式 · 给 harness 读）

> 输入：一句人话需求（例："把深衣改成窄袖便服"、"半臂加接袖变长袖"）。
> 输出：**一份能跑的版型程序**（或一组夹具），以及闸门报告。**不许交"说明"当结果。**

---

## 第 0 步 · 先判级（不判级就动手 = 必然退化成"复制一份程序改常量"）

对着下表选**最轻**的一档。判错方向（把参数级做成结构级）比做错数值更糟。

| 档 | 判据（满足即属本档） | 动作 | 产物落在哪 |
|---|---|---|---|
| **参数级** | 只改"数值"，几何拓扑不变（衣长、总长、通袖、开口宽、压边宽…） | 在 `patterns.json` 的 `run.fixtures` **加一组夹具** + `modes` 加一条说明；**不新建程序** | 原 `pattern/*.py` 不动 |
| **结构级** | 多/少一道**缝、一个片、一处结构**（加接袖、换袖型、加三角、改领条条数） | **用 Δ 派生新程序**：允许 `from parent import ...` 取用父版型的片，**禁止复制父版型源码**；写 `DELTA = ops + knobs + delta账本 + invariants` | 新目录 `hanfu-<名字>/pattern/build.py` |
| **裁法级** | 换**裁剪方式**（分裁 ↔ 通裁），前后片关系变了 | 新谱系根：新项目、新程序、新闸门口径 | 新项目目录 |

判级自检三问：
1. 新旧两件衣的**裁片数量**一样吗？不一样 → 至少结构级。
2. 袖是不是从"布的一端"变成"另裁一片"（或反过来）？是 → 裁法级。
3. 只用改一个数字就能得到它吗？能 → 参数级。

> 反例（历史踩过）：`jiexiu` 本该是 `banbi + 一道袖缝`（结构级派生），当年被做成"拷贝一份程序改常量"；
> `shenyi V1/V2/V3` 本该是 **1 个程序 + 3 组夹具**（参数级），当年被做成三份拷贝。**不要重犯。**

---

## 第 1 步 · 参数级怎么做

1. 打开 `hanfu-studio/patterns.json`，找到该版型的 `run.fixtures`，**追加**一组：

   ```json
   "fixtures": { "V3": { "L_BODY": 195, "GARMENT_L": 770 },
                 "V4": { "L_BODY": 240, "GARMENT_L": 820 } }
   ```

2. 同一条目里 `modes` 追加：`{"id": "V4", "label": "中长便服", "note": "衣长 240（=袖口），总长 820"}`。
3. `sizes` 也要带上这个键（`{"—": ["V1","V2","V3","V4"]}`），否则界面上选不到。
4. 跑：`python kit/scripts/build_kit.py` 让清单同步。

**注意**：`L_BODY` 之类的旋钮若已在 `knobs` 里，其实不改夹具也能在界面上拖；加夹具是为了"一键回到这个状态"。

---

## 第 2 步 · 结构级怎么做（Δ 派生）

1. 选**父版型**（几何上最接近的那个），确认它的 `build.py` 里各"片"是可单独取用的函数（如 `back_half()` / `front_panel()` / `sleeve_piece()`）。
2. 新项目里写**一个** `build.py`：

   ```python
   import sys; sys.path.insert(0, "<workspace>/<父项目>/pattern")
   import build as parent            # 取用父版型的片，不复制源码
   DELTA = dict(ops=["set_sleeve_plan", "add_piece"], knobs={...},
                delta={"衣长": +30.0}, invariants=[...])
   ```

3. **账本**：与父版型的每一处差异，要么是 0，要么写进 `delta`（明示量）。写不出明示量的差异＝你没想清楚。
4. 与父版型**逐点对账**（同一套参数重建父版型，比最大点距）：差异必须等于账本值。

> 参考实现思路（不要复制它的代码，只看形状）：v0.2 的 `patterns/jiexiu.py` 曾做过 5 个 op 的 Δ 派生，
> 对账 16/16、最大偏差 0.000mm。**它已随 v0.2 删除，只记结论。**

---

## 第 3 步 · 裁法级怎么做

新项目 + 新程序 + 新闸门。**不要**试图让一个程序兼容两种裁法。

- 分裁：一组闭合裁片（后片/前片/袖/领条…），闸门看**门襟越中量**、接袖片是否存在。
- 通裁：一块布 + 折叠序列（折线/剪口/幅缝），闸门看**通袖=幅数×幅宽**、**前中开口贯通**。
- 两者判据不同，混着写必然出错（见 `04-口径清单.md`）。

---

## 第 4 步 · 跑闸门（分层，别跳过）

```bash
# 有原型：先参照闸门
cd <workspace>/hanfu-cad && python verification/overlay.py front back      # 叠合 IoU
cd <workspace>/hanfu-cad && python verification/verify.py                  # 形制核对表
# 无原型：自洽 + 对账 + 人审签收
cd <workspace>/hanfu-studio && python selftest.py                          # 全链路
# 统一报告（含四项工程可行性）
python -c "import sys;sys.path.insert(0,'.');import adapters as A;r=A.generate_all('<pid>','<size>');print(r['gates']['summary'])"
```

判定：
- **有原型**：叠合 IoU ≥ 0.85 合格（≥0.90 优）；形制核对表 0 项 FAIL。
- **无原型**：自洽/对账产生 WARN 可以，但必须**人审签收**（`signoff.json`）。
- **失败不硬打回**：WARN 只报错示意；把"差多少"写清楚，交人确认。

## 禁止清单（做过一次就够了，别再犯）

- ❌ 把多个版型合并成"万能参数化引擎"
- ❌ 往共享层加"服饰语义"（领/襟/衽 之类的概念进通用内核）
- ❌ 用 YAML-DSL 描述版型（会把几何压成参数表，正是魔法系数的来源）
- ❌ 造自动化的许愿引擎/流水线（交互必须面向 harness）
- ❌ 用"复制一份程序改常量"冒充派生
