# hanfu-studio · 版型工作台（框架层）

**这里没有几何。** 它是壳：选型 → 参数 → 预览，出图一律调用各项目**已有的** build/make 脚本。

## 核心设计（口径，2026-11-03 定；改代码前先看这一节）

1. **每个版型一种程序。** 版型知识（贝塞尔控制点、G1 圆角、刀口位置、门襟偏角）写在
   **这个版型自己的程序**里，不抽成共享参数表，也不靠"复制父版型源码改常量"得到新衫。
2. **父程序专门逆向出版型的程序。** 父程序的产出物是**程序**，不是图纸：
   实物 / 官图 / 图纸 → 量图 → 版型程序；一句话需求 → 判级（参数级 / 结构级 / 裁法级）→
   改夹具 / 派生程序 / 新谱系根。**出口永远是 `patterns/<版型>/build.py`。**
   这一层的判定与派生由 harness（AI 会话）执行，软件只承载状态、导出接口文件。
3. **四个核心设计功能**（＝下面「四层结构」那四层，名称沿用 11-02 定的原话）：

| 核心功能 | 做什么 | 在哪 |
|---|---|---|
| 极简 SVG 预览 | 矢量直画到 Canvas（不转 PNG）：滚轮缩放、拖拽平移、图层开关、点选组件高亮 | `svgview.py` |
| 图形化编剧参数子程序 | 参数滑杆＋数值框，改完即时重绘；通裁的旋钮直接写进夹具 | `studio.py` 参数区 + `adapters._args` |
| 选型编辑组件库 | 版型树 → 号型 → 组件树（裁片 / 区块），点组件＝预览里高亮 | `studio.py` 左栏 + `library/` |
| 图形化父程序 | 顶栏「逆向 / 许愿 → 接口文件」「一键生成」，承载状态并交接给 harness | `studio.py` 顶栏 + `adapters.py` |

## hanfu-studio 之外的项目：现状是混杂的（事实，不是要清理的对象）

`hanfu-cad` / `hanfu-jiexiu` / `hanfu-shenyi` **不是干净的"版型程序库"**，里面同时躺着三类东西：

| 类别 | 是什么 | 例子 | 与父程序的关系 |
|---|---|---|---|
| ① 版型程序本体 | 几何、放码、出图、回传 pieces | `pattern/build.py`、`make.py`、`export_dxf.py` | **父-子关系只对这类成立**：父程序调用它、保护它 |
| ② 重整前各自发明的分散组件与参考 | 各项目自己长出来的验证脚本、对比图、图源、存档定稿 | `verification/{overlay,fit,report}.py`、`sources/`、`archive/`、`_cmp*.png`、`尺码资料核验.md` | 史料：口径各管各的，不横向通用，父程序不依赖 |
| ③ studio 重整时修改 / 新增进去的东西 | 为接通父程序而改的构建与导出 | 11-02 改的 `build.py` 派生量重算、`export_dxf_whole.py`、`export_dxf_whole_v1.py`、`直交一体_盲区解说.md` | 需求来自父程序，但代码住在子程序里 |

所以：**别假装这些目录是干净的，也别为了"干净"去重写几何。**
父程序依赖的只有 ①；②③ 只影响"读代码时会不会误会"。要动它们时，先分清这一处属于哪一类。

## 为什么是"两个根一个壳"

`分裁` 与 `通裁` 不是同一个底层逻辑，硬合并只会得到假统一：

| | 分裁（半臂 / 接袖） | 通裁（深衣 / 直领交襟） |
|---|---|---|
| 版型是什么 | 一组裁片，每片一条闭合轮廓 | 一块布 + 折叠序列（段 / 折线 / 剪口） |
| DXF | 每片一条轮廓 | **整衣一片**轮廓，折线剪口另设图层 |
| 图纸 | 裁片图（各片排开标尺寸） | 顺序图（材料→对折→剪开→压领→平铺） |
| 参数 | 号型 + 放码 | 旋钮（衣长、总长…） |

所以：几何留在各自项目里，壳只认「脚本 + 参数 + 产物」。

## 通裁的"整衣 DXF"（2026-11-02 接入）

通裁现在也能出 DXF：`hanfu-shenyi/pattern/export_dxf_whole.py`（深衣 产物下拉里选
"整衣 DXF"，或"导出产物"时自动附带）。口径：

- **一条连续闭合外轮廓**：裳·后(3幅) + 衣(4幅·中段对折) + 裳·前(3幅)，腰线处因裳窄于布片而成台阶；
- **前中开口贯通到摆**：±80 两道剪开、中间 160 直边缺口挖掉 → 两襟独立可滑（"左右衣襟活动"）；
- **几何里没有"交"**：交襟是穿法（两襟交叠着系，交叠量决定上身领形直/交），只进标注；
- **收褶不画**：裳腰 1500(3幅) 接衣身摆线 ±370，差值收褶吃掉（推算比 ≈2:1），只在标注里写；
- 领条另裁（直条绕颈后）；腋点 ±370 为原图记号。
- **预览里的外侧括号弧＝折叠箭头**（上段向下折、下段向上折），不是版型线；
  已单独归到 `FOLDARROW` 图层，可在底部图层开关里关掉。预览也已修正 `Z` 闭合，
  布片矩形不会缺左边。

数值全部取自 build_shenyi.py 的 DEF / 旋钮，脚本自身不新增尺寸（唯一补充 N_SHANG=3，
来自剪裁图实测：上/下块各 3 幅）。

## 四层结构（2026-11-02 重做）＝ 上面第 3 条的四个核心设计功能

> **名称说明**：② 叫「图形化编剧参数**子程序**」，这个"子程序"指**本软件内部的一个功能模块**
> （负责把参数编成命令行）；与"版型子程序"（`hanfu-cad` / `hanfu-jiexiu` / `hanfu-shenyi`）
> **不是一回事**。两处都用"子程序"是 11-02 的既定命名，不改，读到时按上下文区分。

| 层 | 做什么 | 在哪 |
|---|---|---|
| ① 极简 SVG 预览 | **矢量**直画到 Canvas（不转 PNG）：滚轮缩放、拖拽平移、图层开关、点选组件高亮 | `svgview.py` |
| ② 图形化编剧参数子程序 | 参数滑杆＋数值框，改完即时重绘；通裁的旋钮直接写进夹具 | `studio.py` 参数区 + `adapters._args` |
| ③ 选型编辑组件库 | 版型树 → 号型 → **组件树**（裁片/区块），点组件＝预览里高亮 | `studio.py` 左栏 + `patterns.json` |
| ④ 图形化父程序 | 顶栏摆出「逆向入口」「许愿入口」「一键生成」；两个入口都**面向 harness**（量图/判级/派生由 AI 会话做，软件承载状态并交接） | `studio.py` 顶栏 + `adapters.py` |

### 手工编辑（排料层，不碰几何）
预览就是编辑画布，编辑只改**摆放**，不改版型程序：

- **移动组件**：点中裁片后拖动；该裁片轮廓与邻近的缝线/刀口/尺寸/文字一起移动。空白处拖动才是平移画布。
- **新建组件**：组件库下方「新建」→ 输入 `宽×高`（mm），在视口中心放一个矩形裁片占位。
- **复制 / 粘贴**：选中组件后 `Ctrl+C` / `Ctrl+V`（或「复制」「粘贴」按钮），副本偏移 40mm 并自动命名。
- **重置布局**：「重置」清除所有移动、新建、复制。
- 组件归属：SVG 里 `<片名>_ot` 的轮廓是锚，其它层（SEAM/NOTCH/DIM/LABEL…）按最近裁片框归组，
  所以拖片时标注会跟着走；BLOCK/SCALE 与标题栏保持不动。
- **导出**：「导出产物」写到 **studio 自己的** `out/exports/<版型>_<号型>/`，
  内含子程序产物 + `手工布局_<版型>_<号型>.svg/.png` + `手工排料_….dxf/.pieces.json`。
- 切版型会清空布局；改号型/模式/参数只重绘几何，移动与新增的组件保留。

### 可裁排料 DXF 与布局工程
手工编辑不再只是“看得见”，可以直接产出生产文件（全部落在 `hanfu-studio/out/`）：

- **裁片来源**：`build_svg` 会带回子程序生成的 `.pieces.json`（真实轮廓、布纹、刀口、片名），
  界面上的移动/新建/复制最终都折算成裁片的 `ox/oy/box` 再出图。
- **导出排料**：左栏「导出排料」→ `out/排料_<版型>_<号型>_<时间>/手工排料_….dxf`；
  「导出产物」也会在 `out/exports/<版型>_<号型>/` 附带同名 DXF 和 `.pieces.json`。
  图层：`CUT_裁剪`（轮廓）、`GRAIN_布纹`、`NOTCH_刀口`、`TEXT_文字`、`DIM_标注`；
  选缝份时另有 `NET_净样` 层（净样与裁剪线都保留）。
- **缝份**：左栏「缝份」可选 净版 / 5 / 10 / 15 mm。用 shapely 做闭合轮廓外偏移；
  尖角按斜接处理，窄条/三角的端点会有正常的外扩。
- **布局工程**：左栏「保存布局 / 打开布局」→ `out/layouts/*.layout.json`，记录版型、号型、模式、参数、
  缝份、每个组件的位移、新建/复制组件（含真实裁片定义）与图层可见性。
  打开时自动切回对应版型/号型/模式/参数，再恢复布局。
- **边界**：排料 DXF 是“按当前版型程序的几何排料”，不会把移动/新增写回版型程序的几何；
  通裁没有裁片列表，整衣 DXF 仍由「导出产物」里的子程序脚本出。

### 注册版型（把已有的版型程序登记进来）
左栏「注册版型」→ 填 **项目目录 + 脚本 + 运行方式**（+ 模式/号型或夹具），点「预检」逐条核对：
项目目录存在、脚本存在、**脚本可编译**、运行方式合法、argstyle 占位只允许 `{sex}{size}{out}{profile}{ease}`、
模式与夹具键一致、号型与夹具键一致、id 未占用。**预检不过不写入**。
写入 = `patterns.json` 里加一条 `custom: true`（**只登记，不复制源码**）；`adapters.unregister_pattern()`
可注销，内置版型拒绝注销。注册完立刻能走「预览 / 一键生成 / 形制核对」同一条链路。

### 项目管理（studio 可写）
左栏「项目管理 / 新建项目」，选型树按 **项目 → 裁法 → 版型** 分组。

- **内置项目**（hanfu-cad / hanfu-jiexiu / hanfu-shenyi）来自 `patterns.json`，只读；
  可用「另存为」复制成一个自建项目（只复制版型引用，不复制源码）。
- **自建项目**登记在 `hanfu-studio/projects.json`；项目目录默认 `workspace/<项目名>`，
  内含 `project.json` 清单。可：新建（可勾选初始版型）、重命名、更改目录（只改登记路径，
  不移动已有文件）、添加/移除版型、另存为、打开目录、删除。
- **项目只组织已注册版型**，不复制/不生成版型源码；空项目在树里显示「空项目」。
- **删除项目**：先弹「删除项目 · 确认文件」，列出项目目录内**全部将被删除的文件/子目录**
  与总大小，必须勾选确认后才能删除；后端只删带匹配 `project.json` 的 studio 项目目录。
  内置项目目录、workspace 根、hanfu-studio 等受保护路径不会被删除；
  不满足条件时只移除项目登记并明确提示。
- 引用其他项目的版型源码不在项目目录里，删除项目不会动它们。

### CAD 协同（SVG / DXF 导入导出）
左栏「CAD 协同」是独立窗口，不改造版型程序，专门和外部 CAD 交换图纸。

- **导入**：
  - SVG：直接按 `<g id="图层">` 读入，图层变成可选/可拖的组件；
  - DXF：`dxf_io.py`（ezdxf 子进程）读取 LWPOLYLINE/POLYLINE/SPLINE/ARC/CIRCLE/ELLIPSE/
    LINE/TEXT/MTEXT，INSERT 递归展开；按 `$INSUNITS` 折算 mm，图层/颜色/文字保留，
    曲线按 0.5mm 采样为折线（第一版不做圆弧原样回写）。
- **修改**：拖拽移动整个图层，`Ctrl+C/V` 复制图层，删除＝删手工副本 / 隐藏原图层，
  图层开关控制显示；导出时隐藏图层不写出。
- **导出**：
  - SVG：按图层写 `<g id="图层">`，保留位移；
  - DXF：写成 LWPOLYLINE/LINE/CIRCLE/TEXT，保留图层名、true color、文字高度/旋转；
    同时在 DXF 旁写 `.scene.json` 中间文件。
- **落地**：导入/导出文件默认放 `hanfu-studio/out/interop/`（导出对话框可改）；
  DXF 依赖 ezdxf，GUI 进程不直接 import，由 `dxf_io.py` 子进程处理。
- **边界**：第一版是图层级修改（移动/复制/隐藏），还没有逐点改曲线、圆弧保真回写和块定义编辑。

### 共享组件库（studio 内部资产）
不是去索引三个子项目的裁片，而是 studio 自己管理的跨项目组件资产：

- **默认收录**：打开「共享库」时自动收集**所有已注册项目**的组件：
  - 分裁（对穿交半臂 / 对穿交接袖）→ **项目裁片**；
  - 通裁（深衣 V2/V3、原始直领交襟衣 V1）→ **项目区块**（通裁没有独立裁片，
    用 上衣/裳·前/裳·后/领条 等功能区块表示）。
  - 目录缓存在 `hanfu-studio/library/_project_catalog.json`；项目脚本变更（mtime 变化）会自动失效重建。
  - 项目默认组件**不能删除**；需要改动可另存为自存组件。
- **裁法隔离**：分裁只和分裁互通，通裁只在通裁内部互通；跨裁法插入会被拒绝。
- **存自存组件**：在预览里选中裁片 → 「存入当前选中组件」→ `hanfu-studio/library/<id>/`
  （`component.json` + `versions/1.json` + `thumb.png`）。
- **插入**：「插入到当前布局」＝**引用实例**，记录 `library_id + version + source + kind`；
  组件树出现「共享库引用」分区；布局工程、接口文件都会带引用元数据。
- **断开引用**：保留当前几何快照，仅去掉库引用；删自存组件也不会破坏已保存布局。
- **通裁怎么用**：通裁区块是**参考/复用区块**，插入后用于布局/交接；整衣 DXF 仍是
  「导出产物」里子程序出的一条连续外轮廓，不会因为插入区块而改成独立裁片。
- **不做自动参数适配**：跨版型插入后按当前版型手动调整。
- **接口文件**：导出给 harness 的 JSON 增加 `library` 字段，列出当前布局的库引用。

### 可复用模式（一级概念）
`patterns.json` 每个版型带 `modes`（基准档 artifact/vendor 或夹具 V1/V2/V3）+ `ease`（放量档），
每条带一句说明，界面上直接可选、可一键生成。

### 批量生成（每个可复用模式各一整套）
界面顶栏「批量生成」或 `python batch_cli.py all`：对每个模式（分裁＝基准档 × 放量 × 号型；通裁＝每个夹具）
各跑一套，落到 `out/batch/<版型>_<时间>/<模式_性别_号型>/`，内含
SVG / 裁片 JSON / DXF（通裁另含整衣 DXF）/ 尺码表（分裁）/ `形制核对/`，并生成 `批量清单.md`（每组文件数 + 通过·示意数）。
取中码与全码两档：中码档四版型合计 11 组、约 45 秒。

### 一键生成
`adapters.generate_all()`：出图 → 落盘全套产物（分裁 svg/dxf/pieces/尺码表；通裁加整衣 DXF）→ 返回清单。

## 软件日志与自检
- **日志**：`logs/studio-YYYY-MM-DD.log`（打包后写 `%LOCALAPPDATA%\hanfu-studio\logs`）。
  每次出图/产物/导出/异常一行；脚本失败连 stderr 全文一起记。顶栏「日志」按钮直接打开。
- **自检**：`python selftest.py` 走完所有版型×号型×产物，把结果写进同一份日志；读日志即知问题。
  （它已经抓到过真 bug：jiexiu artifact 档 `sizing.sleeve_root` 硬取 `p["WRIST"]` → KeyError，
  导致 studio 里 jiexiu 女码从来没出过图。）
- **看界面**：`python shot.py "<窗口标题>" out.png`（PrintWindow 抓图，不抢焦点）。
- **打包版自检**：`dist\hanfu-studio.exe --check-library` → 写 `out/library_check.txt`，
  首行 `OK components=N`；`--check-projects` → `out/projects_check.txt`，首行 `OK projects=N`；
  `--check-cad <某个.dxf>` → `out/cad_check.txt`，验证打包版 DXF 导入/导出。
  用来确认换机/重打包后项目组件目录、项目登记与 CAD 协同都能正常读取。

## 目录

```
hanfu-studio/
  studio.py       tkinter 界面（左选型/号型/组件，中预览，右参数）
  adapters.py     适配层：调脚本出 SVG、调 Edge 转 PNG（无几何）
  svgview.py      矢量预览 / 手工排料（移动、新建、复制粘贴）
  layout_dxf.py   排料 DXF 生成（ezdxf；缝份用 shapely，独立子进程）
  dxf_io.py       CAD 协同：DXF↔SVG/场景 JSON（ezdxf 子进程）
  library/        共享组件库（studio 内部资产，每个组件一个目录）
  projects.json   自建项目登记（运行时生成；内置项目来自 patterns.json）
  patterns.json   版型注册表：脚本路径 + 号型/夹具 + 可调旋钮
  config.json     指向"能跑这些脚本的 python"
  build_exe.py    PyInstaller 打包
```

## 跑

本机带 tkinter 的解释器（其它几个都没有）：

```
<你的 python 路径> studio.py
```

## 打包 exe

```
<上面那个 python> build_exe.py        → dist\hanfu-studio.exe
```

exe 里不带几何：它照样调用各项目的 `pattern/*.py`，所以三个项目要留在原位（与 exe 同一仓）。
解释器优先用**随包 `runtime/`**（embeddable + ezdxf/numpy/PIL/shapely/fontTools），换台电脑不装 Python 也能出图；顺序见 `adapters.python_exe()`。

## 接一个新版型

在 `patterns.json` 里加一条：

